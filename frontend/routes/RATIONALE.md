## Base element resets moved into `@layer base`
**Context** — `routes/tailwind.css` reset headings (`h1..h6 { margin: 0 }`) and `routes/app.css` reset links (`a { color: inherit }`) as unlayered rules, while every Tailwind utility lives in `@layer utilities`. Unlayered declarations beat layered ones regardless of order, so both resets silently won over the utilities: `mx-auto`/`mt-*` on any heading and `text-*` on any anchor did nothing. It surfaced as a centred welcome section whose `<h2>` sat flush left while the `<p>` beside it, carrying the identical `mx-auto max-w-760`, centred correctly.
**Decision** — Both resets now sit in a single `@layer base` block in `routes/tailwind.css`. The link reset was moved out of `app.css` because that file is imported before `tailwind.css`; an `@layer` block there would register `base` ahead of Tailwind's own `@layer theme, base, ...` statement and push the theme layer after it.
**Rationale** — Layering the resets is the fix at the source: it restores the utilities on the 19 headings and 2 anchors across the app that were already asking for them, instead of working around a dead utility per call site. The cost is that those elements now actually get their declared margins — on this project's 1px spacing scale that is a 2–6px shift, and only `routes/+page.svelte` and `webpage-builder/pages/WebpageConfig.svelte` are affected outside `welcome/` and the dev-only `develop-ui` demos. The storefront is untouched: it builds from `webpage/routes/tailwind.css` and has no heading or anchor reset.
